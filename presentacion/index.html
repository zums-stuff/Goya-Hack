El período de prueba

Tres salidas, ningún funds secuestrado

Con comprador y vendedor juntos en el campus, el comprador tiene tiempo de encender el equipo, ponerlo a prueba en clases o tareas y verificar que funciona. Lo que pase después decide el contrato.

Ahappy
Si sirve → confirmas y el contrato libera los fondos al instante
Firma de la plataforma + la llave de arbitraje sobre Stellar. El vendedor recibe su XLM. Comisión del 2% (0% en hackathon).
Bauto
Si se te olvida conformar → el sistema auto-libera al expirar el tiempo
El TTL vence y un cron resuelve solo, a favor del vendedor. Nadie puede sequestrar los fondos.
Cdisputa
Si el equipo viene dañado → se congela y se ancla la evidencia
Reporte con foto y descripción → el escrow queda congelado y el hash de evidencia se ancla en el libro mayor de Stellar. Se evita el riesgo para el comprador.
Rama C · La evidencia

Anclar la evidencia en el ledger

Cuando el comprador reporta un daño, la evidencia no se queda en nuestra base de datos: se escribe en la red Stellar mediante manageData, y para hacerlo…

⚿

La operación va en la cuenta de custodia

El manageData no lo firma la plataforma: lo firma la cuenta de escrow, que exige 2 de 2. El ancla hereda la misma garantía que el dinero.

⛓

Prueba pública e inalterable

Cualquiera puede verificar que la evidencia existía antes de que la disputa se resolviera. El hash es inmutable una vez escrito.

// lib/stellar.ts — anchorDataEntry
Operation.manageData({ account: escrowAccount, name: 'gremium:evid:<id>', value: hexHash })
// límites del protocolo: name ≤ 64 bytes · value ≤ 64 hex chars
// requiere 2 firmas sobre la misma cuenta 2-de-2
